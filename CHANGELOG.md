# Changelog

## 4.3.0

Full icon coverage

- Every glyph in Discord's current icon set is mapped: 246 named SVG components from the web bundle, resolved by path signature. Camera, microphone, headphones, wrench, crown, bookmark, warning, soundboard, stage, clips, tag, upload and the formatting icons no longer keep Discord's vector shapes
- 33 new 16 x 16 pixel icons (137 total), including formatting, file, envelope, tag, heart, leaf, share, server, soundboard, stage and media controls. The gallery in `docs/icons.html` lists them all
- Variants that share a badge (lock, warning, spoiler) resolve to the matching composite pixel glyph. Previous signatures stay in place, so older clients keep their icons too

## 4.2.1

Windows installer

- It refused nothing before: it wrote Vesktop's settings even while Discord was running, and the client rewrites those files on exit, so the plugin could vanish. It now stops first and says why
- The plugin download reports the real error instead of "could not be downloaded", retries with TLS 1.2 and falls back to `curl.exe` on older Windows PowerShell
- A failed splash download no longer stops the script before the plugin is installed
- `-Doctor` reports the clients, whether the plugin build downloads, the plugin folder, `vencordDir`, whether the plugin is enabled and which clients are running
- The plugin step checks that the four files landed and names the missing ones

## 4.2.0

More clients

- The installers also cover Dorion, Legcord, GoofCord and Replugged, each in its own theme format, and remove the theme from them on uninstall. Paths and formats come from each client's source code; they were tested against stand-in folders, not the real apps
- `ReCord.user.css`: the same theme as a userstyle, for Discord in a browser through Stylus. Generated by the build and covered by `npm run check`
- Yapfast and other native clients cannot be supported: they draw their own interface and load no CSS. moonlight has no theme loader of its own, so it stays manual

Performance

- Low power also hides profile effects, video banners and the reaction glow, and flattens gradient usernames, through the new `--rl-lite` variable
- `install.sh --doctor` reports the installed clients, the GPU and whether Vesktop has hardware acceleration on. It changes nothing: GPU flags are left alone on NVIDIA, AMD and Intel alike

## 4.1.1

- Fixed the message hover bar (add reaction, reply, forward, more) being cut off. Since 3.5.0 every message, member row and server icon had `contain: layout paint style`, and paint containment clips anything that sticks out of the box; the bar sits above the top edge of its message. The rules are removed: they had shown no measurable gain. Server badges that overflow their icon were affected the same way

## 4.1.0

Performance of the website, measured in Firefox, where it was slow.

- Scanlines are a tiled image instead of a repeating gradient. Firefox re-rasterized the 3px gradient over the whole viewport on every scroll frame. Average frame while scrolling: 42 to 44 ms before, 16.5 ms after (the 60 fps cap); worst frame 134 to 146 ms before, 23 to 29 ms after
- Removed `mix-blend-mode: multiply` from the scanline overlay and `backdrop-filter: blur()` from the top bar, and two color filters on large elements
- The demo page and the theme's full-screen CRT layer use the same tiled image
- Measured by removing one suspect at a time: the demo iframe, the skyline and the shadows were not the cause, and neither was the layer being fixed

Theme

- Low power option in the plugin and the configurator: turns off the scan beam, grain, flicker and the constant animations, for clients that composite on the CPU

## 4.0.0

Installing

- The installers now set up the startup splash. Before, the image and its settings were never copied, so a fresh machine kept Vesktop's default splash
- The plugin is installed by default on Linux, macOS and Windows. A ready-made build is downloaded, so the machine does not need git or Node.js; if it is not available the Linux and macOS installer builds it locally. `--no-plugin` (`-NoPlugin` on Windows) skips it
- The plugin is switched on automatically
- Uninstalling restores the settings it changed: theme list, splash colors, plugin entry and Vencord location
- New workflow `plugin.yml` builds Vencord with the plugin and publishes it as the `plugin` release for the installers
- `--plugin` is still accepted and does nothing, since it is the default

Website

- The install card detects Windows, macOS or Linux and shows the right command, with tabs to switch and options for theme only and uninstall. Phones get a note that themes are desktop only

Plugin performance

- Menus and dialogs are counted at most once per frame with a cheaper lookup, instead of on every DOM change
- The disabled-sound list and the per-sound themes are parsed once and reused until they change
- Pointer, click and key listeners are passive and return early when interface sounds are off
